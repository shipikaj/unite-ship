# Google Analytics 4 Custom Report Fields

**65 metrics · 396 dimensions**

Complete list of Google Analytics 4 fields that can be used in a Unite custom report. Use a custom report when the prebuilt reports do not include the fields you need.

## Dimensions and metrics

There are two types of fields: dimensions and metrics.

- **Dimensions** (type `STRING`) are text values that describe or split your data, such as campaign, country, device, or page path.
- **Metrics** (type `INTEGER` or `FLOAT`) are numeric values, such as sessions, active users, and revenue.

Rate metrics, such as bounce rate and engagement rate, are returned as a fraction. For example, 0.25 means 25%.

## Combining dimensions and metrics

The Google Analytics 4 API limits the number of fields in one request to **9 dimensions and 10 metrics**. Not every dimension can be combined with every metric. To check whether a combination is supported, use the [GA4 Dimensions & Metrics Explorer](https://ga-dev-tools.web.app/ga4/dimensions-metrics-explorer/).

### Google Analytics 4 Cohort fields

The Cohort category of the Google Analytics 4 connector includes 6 fields.

| **ID** | **Type** | **Name** | **Description** |
|---|---|---|---|
| `cohort` | STRING | Cohort | The cohort's name in the request. A cohort is a set of users who started using your website or app in any consecutive group of days. If a cohort name is not specified in the request, cohorts are named by their zero based index such as cohort_0 and cohort_1. |
| `cohortNthDay` | STRING | Daily cohort | Day offset relative to the firstSessionDate for the users in the cohort. For example, if a cohort is selected with the start and end date of 2020-03-01, then for the date 2020-03-02, cohortNthDay will be 0001. |
| `cohortNthMonth` | STRING | Monthly cohort | Month offset relative to the firstSessionDate for the users in the cohort. Month boundaries align with calendar month boundaries. For example, if a cohort is selected with the start and end date in March 2020, then for any date in April 2020, cohortNthMonth will be 0001. |
| `cohortNthWeek` | STRING | Weekly cohort | Week offset relative to the firstSessionDate for the users in the cohort. Weeks start on Sunday and end on Saturday. For example, if a cohort is selected with the start and end date in the range 2020-11-08 to 2020-11-14, then for the dates in the range 2020-11-15 to 2020-11-21, cohortNthWeek will be 0001. |
| `cohortActiveUsers` | INTEGER | Cohort active users | The number of users in the cohort who are active in the time window corresponding to the cohort nth day/week/month. For example in the row where cohortNthWeek = 0001, this metric is the number of users (in the cohort) who are active in week 1. |
| `cohortTotalUsers` | INTEGER | Cohort total users | The total number of users in the cohort. This metric is the same value in every row of the report for each cohort. Because cohorts are defined by a shared acquisition date, cohortTotalUsers is the same as cohortActiveUsers for the cohort's selection date range. For report rows later than the cohort's selection range, it is typical for cohortActiveUsers to be smaller than cohortTotalUsers. This difference represents users from the cohort that were not active for the later date. cohortTotalUsers is commonly used in the metric expression cohortActiveUsers/cohortTotalUsers to compute a user retention fraction for the cohort. The relationship between activeUsers and totalUsers is not equivalent to the relationship between cohortActiveUsers and cohortTotalUsers. |
